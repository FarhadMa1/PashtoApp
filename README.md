# PashtoApp

iOS app that will teach Pashto from scratch. The app target is a SwiftUI shell. `PashtoCore` decodes the lesson content bundle, folds text for comparison, and validates that bundle. Its tests run on Linux. Quizzes, review scheduling, streaks, pronunciation playback, and screens beyond the placeholder are not implemented.

The UI language is English. Pashto text, when it is added later, will be right-to-left per text block.

## Layout

```
project.yml                 XcodeGen spec. Edit this, not the Xcode project.
PashtoApp.xcodeproj         Generated by XcodeGen and committed. Shared scheme: PashtoApp.
PashtoApp/                  SwiftUI app target (iOS 17+). Placeholder root view.
Packages/PashtoCore/        Pure Swift package. No Apple-only frameworks.
Tools/PashtoContentTool/    Merges `content/` and runs the release gate. The app does not build it.
content/                    Unit sources, `release-units.json`, `id-registry.json`, and generated `content.json`.
scripts/linux-guard.sh      Fails if PashtoCore uses an Apple-only API.
.github/workflows/          Linux `swift test`, merge check, and validate.
docs/ARCHITECTURE.md        How the pieces fit.
docs/decisions/             Architecture decision records.
```

The app target depends on `PashtoCore`. The package is where future lesson and quiz logic goes, so it can be tested on Linux without a Mac.

## Bundle identifier

`com.mangallabs.pashto` is the final bundle id, chosen for Mangal Labs. It is set in `project.yml` (`PRODUCT_BUNDLE_IDENTIFIER` and `bundleIdPrefix`) and in the committed Xcode project.

No development team is set in the project. Xcode Cloud, or Xcode on a Mac, supplies the team at signing time.

## Test the core package on Linux

Requires Swift 6.0 or newer (CI uses Swift 6.2.4). From the repository root:

```bash
swift test --package-path Packages/PashtoCore
```

That does not build the iOS app. The app target needs Xcode on macOS.

The same package must stay free of Apple-only frameworks and of the process-global clock and locale. From the repository root:

```bash
./scripts/linux-guard.sh
```

CI runs that check before `swift test`. It then checks that `content/content.json` matches `pashto-content merge`, and runs `validate --mode dev` and `validate --mode release`.

```bash
swift test --package-path Tools/PashtoContentTool
swift run --package-path Tools/PashtoContentTool pashto-content merge --check
swift run --package-path Tools/PashtoContentTool pashto-content validate --mode dev
swift run --package-path Tools/PashtoContentTool pashto-content validate --mode release
```

`content/id-registry.json` is empty because no id has shipped. `content/release-units.json` is empty because 45 of the 51 items are not verified. The release command still runs against that list.

## iOS builds

Primary path: **Xcode Cloud**, using the committed `PashtoApp.xcodeproj` and the shared `PashtoApp` scheme. No `ci_scripts` hook is required, because the project is already in git. See [docs/decisions/0001-project-structure.md](docs/decisions/0001-project-structure.md) for why the generated project is committed instead of being created in `ci_post_clone.sh`.

There is no macOS GitHub Actions job. Those runners cost money and need a separate approval. They remain the fallback if Xcode Cloud is unavailable: a macOS runner can `xcodebuild` the committed project without installing XcodeGen.

This skeleton was not compiled with Xcode. Linux CI only runs `swift test`.

### Xcode Cloud workflow

Create the workflow in App Store Connect (or Xcode) against this repository:

1. Project: `PashtoApp.xcodeproj`
2. Scheme: `PashtoApp` (shared)
3. Xcode 16 or newer, so the Swift 6 language mode is available
4. Set the Apple Developer team. Register `com.mangallabs.pashto` to that team before an archive is distributed.
5. Use an archive action when a TestFlight build is actually wanted

### Regenerate the Xcode project

On a Mac with [XcodeGen](https://github.com/yonaskolb/XcodeGen) 2.46.0, from the repository root:

```bash
xcodegen generate
```

Commit `project.yml` and `PashtoApp.xcodeproj` together. Do not hand-edit the `.xcodeproj`.

The project checked in here was generated from that spec. Stock XcodeGen 2.46.0 crashes on the Swift 6.2.4 Linux toolchain while resolving `Bundle(for:)` for its setting presets, so regenerate on a Mac. The Linux run used the same 2.46.0 preset files after skipping that lookup, and a second generate produced the same `project.pbxproj`.

## What is intentionally absent

- The app loading `content.json` into a Release or Debug bundle
- Quizzes, spaced repetition, and streaks
- Audio playback and a pronunciation control
- Any screen besides the placeholder root
- Accounts, networking, and a backend
- On-Demand Resources (deprecated; future audio will be bundled in the app)
